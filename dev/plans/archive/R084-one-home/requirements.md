# R084: One home per rule

## Goal

Every definition has one home and no two rules conflict. Four break
this: the merge decision has a prefix exception another rule
contradicts, the branch close asks twice, this repository's declarations
sit in every project's instructions, and doc verification grades claims.

## Outcomes

1. Who merges has one rule: the seat the supervision declaration names,
   after green. No prefix merges on its own; the merge command stays.
2. A branch has one decision point: with its MR/PR open and green, the
   merging seat merges or discards. The live verify step precedes it.
   The ship command remains the entry for a landed branch outside a run.
3. The global instructions carry only conventions for every project. A
   declaration's one home is the project's instructions, read only
   there by every script and hook; the precedence sentences go.
4. A doc describes its subject: what it is, how it works, how it is
   used. No task, no history, no mark of standing. History and results
   live in the task report: what was done, when, what came of it.
5. Every touched doc is verified by a seat other than its writer: each
   claim against its source, the whole for ambiguity and contradiction,
   and conformity to the writing conventions. One mismatch list, fixed
   in one round; no verdict names, no evidence column.
6. The doc writer's report names, per section, the source it confirmed
   against; the verifier reads it first. A report is never a running log.
7. Nothing is half retired: a search at close finds no occurrence of
   the retired policy, question, sentences, vocabulary or column.

## Constraints

- Simplification only: no new seat, gate or script. Verification reads
  a live system and never changes one.
