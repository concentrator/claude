# R089: Autonomous adopter runs

## Goal

A new project adopts DEV and runs it end to end - start, plan, run, close,
release - in a Claude Code cloud session under `auto` with `Supervisor: AI`,
no human answering, at a cost in proportion to the work.

## Outcomes

1. The toolset installs in a cloud session by a documented step the
   permission classifier admits.
2. No classifier denial stops an action a shipped tier or template could
   cover; a denial the toolset's own rules call for stays.
3. Every gate, check and permission rule the toolset's text cites exists
   in an adopter after install.
4. A file the session may not write is handed to the user with its content.
5. The declared host commands work where the host CLI has REST only.
6. `/dev start` adopts a repository whose `main` already exists.
7. The doc writer and the docs verifier hold a doc to the same bar.
8. A mechanical review fix costs no fresh seat.
9. Planners for dependent tasks run in dependency order.
10. A code defect the docs step finds is fixed, its doc following, within
    the close.
11. The checkpoint report's cost figures come from a tool.
12. A reference doc states each failure behavior once.
13. Code contradicting a written design decision is a reviewable finding.
14. One rule says whether a doc seat may run code to confirm a sentence.

## Constraints

- Close is judged by a fresh re-run of the dogfood runbook in the same
  setup; the runbook lands in this repository first.
- What a seat loads is out of scope: an open initiative carries it.
